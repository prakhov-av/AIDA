# Модель интеллекта AIDA

**Версия:** 0.1 (Draft)

**Статус:** В разработке

---

# Назначение документа

Данный документ описывает интеллектуальную модель платформы AIDA.

Он определяет:

* виды интеллекта, существующие в системе;
* их ответственность;
* взаимодействие между ними;
* место Context Engine в архитектуре;
* принципы формирования инженерного контекста.

Документ является частью базовой архитектуры платформы.

---

# Главная идея

Большинство современных AI-платформ строятся вокруг языковой модели.

AIDA строится вокруг инженерного интеллекта.

Языковые модели являются лишь исполнителями.

Главным активом платформы являются знания проекта, организационная структура и процессы разработки.

---

# Интеллект AIDA

AIDA использует два независимых вида интеллекта.

## Project Intelligence

Project Intelligence представляет собой цифровую инженерную модель проекта.

Он отвечает за понимание самого проекта.

В его состав входят:

* архитектура;
* RFC;
* ADR;
* документация;
* исходный код;
* тесты;
* структура проекта;
* инженерные стандарты;
* история изменений;
* инженерные артефакты;
* связи между всеми объектами проекта.

Project Intelligence отвечает на вопросы:

* Что представляет собой проект?
* Как он устроен?
* Почему были приняты определенные решения?
* Какие зависимости существуют?
* Какие изменения могут повлиять на систему?

---

## Organization Intelligence

Organization Intelligence представляет цифровую модель инженерной организации.

Он отвечает за понимание процесса разработки.

В его состав входят:

* роли;
* команды;
* зоны ответственности;
* процессы;
* компетенции;
* доступные возможности;
* используемые инструменты;
* политики;
* правила принятия решений.

Organization Intelligence отвечает на вопросы:

* Кто должен выполнять работу?
* Какая роль отвечает за задачу?
* Какая последовательность действий является правильной?
* Какие возможности необходимы для выполнения задачи?

---

# Context Engine

Context Engine объединяет оба вида интеллекта.

Он формирует рабочий контекст для конкретной задачи.

Context создается динамически.

Он существует только в течение выполнения задачи.

После завершения задачи контекст может быть уничтожен.

---

# Формирование контекста

Контекст строится из двух источников.

Из Project Intelligence выбираются:

* необходимые документы;
* архитектурные решения;
* связанные компоненты;
* исходный код;
* тесты;
* инженерные стандарты.

Из Organization Intelligence выбираются:

* исполнитель;
* ответственность;
* процесс выполнения;
* необходимые возможности;
* используемые инструменты.

После объединения формируется единый инженерный контекст.

---

# Capability Model

AIDA не связывает роли с конкретными моделями.

Вместо этого используется понятие Capability.

Capability описывает возможность выполнять определенный вид инженерной деятельности.

Примеры:

* Architecture Design
* Code Generation
* Code Review
* Test Generation
* Documentation
* Security Analysis
* Performance Analysis
* Refactoring
* Planning

Роль использует одну или несколько возможностей.

Конкретная AI-модель предоставляет реализацию этих возможностей.

---

# Архитектурные принципы

## Intelligence First

Любое решение должно приниматься на основе интеллектуальной модели проекта.

---

## Context over Prompt

Качество результата определяется качеством сформированного контекста, а не размером промпта.

---

## Capabilities over Models

Система работает с возможностями.

Модели являются лишь реализацией возможностей.

---

## Dynamic Context

Контекст создается автоматически для каждой задачи.

Статические промпты не являются источником истины.

---

## Continuous Intelligence Growth

После завершения каждой задачи интеллектуальная модель проекта должна обновляться.

Новые знания становятся частью Project Intelligence.

# Заключение

Интеллект является фундаментом платформы AIDA.

Языковые модели, внешние сервисы и инструменты рассматриваются как взаимозаменяемые исполнители.

Главной ценностью платформы являются знания проекта, организационная модель и способность формировать правильный инженерный контекст для каждой задачи.

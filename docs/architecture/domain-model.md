# 1. Назначение документа

## Цель

Данный документ определяет доменную модель платформы AIDA (AI Development Agency).

Он является фундаментом всей архитектуры системы и описывает:

- основные доменные понятия;
- архитектурные принципы;
- границы ответственности компонентов;
- ключевые сущности;
- связи между ними.

Документ не описывает детали реализации, структуру базы данных, REST API или пользовательский интерфейс.

Эти вопросы рассматриваются в отдельных RFC и ADR.

---

## Назначение доменной модели

Доменная модель является основным источником истины (Single Source of Truth) для архитектуры AIDA.

Любое архитектурное решение должно соответствовать данной модели.

Если реализация противоречит доменной модели, ошибочной считается реализация.

---

## Область применения

Документ обязателен для всех участников разработки и всех компонентов платформы.

Каждая новая функциональность должна проектироваться в соответствии с данным документом.

---

# 2. Философия доменной модели

## Что такое AIDA

AIDA — это AI Development Agency.

Платформа координирует процесс разработки программного обеспечения, объединяя инженерные роли, знания проекта и автоматизированные рабочие процессы.

Главная задача AIDA — не генерация кода.

Главная задача AIDA — организация инженерной деятельности.

---

## Главная идея

Большинство современных AI-инструментов строятся вокруг одной модели.

AIDA строится вокруг инженерного процесса.

Любая задача рассматривается как последовательность специализированных этапов.

Каждый этап выполняется определенной инженерной ролью.

---

## Человек остается главным инженером

AIDA помогает принимать решения.

Но окончательная ответственность всегда принадлежит человеку.

Архитектурные изменения, изменение требований, конфигурации проекта и объединение изменений в основную ветку требуют подтверждения пользователя.

---

## Контекст важнее модели

Качество результата определяется не столько моделью, сколько качеством предоставленного ей контекста.

Поэтому центральным элементом платформы является **Project Intelligence**.

---

## Project Intelligence

Project Intelligence — это интеллектуальное представление проекта.

Он объединяет всю инженерную информацию, необходимую для принятия решений.

Project Intelligence включает:

- архитектуру;
- RFC;
- ADR;
- документацию;
- исходный код;
- структуру проекта;
- стандарты разработки;
- историю решений;
- результаты ревью;
- связи между артефактами;
- накопленные знания проекта.

Project Intelligence не является обычной базой знаний.

Его задача — предоставить каждой роли только ту информацию, которая необходима для выполнения конкретной задачи.

---

## Роли важнее моделей

AIDA работает с инженерными ролями.

Например:

- Architect
- Developer
- Reviewer
- Tester
- Documentation
- Security
- Performance

Какая именно модель выполняет роль определяется конфигурацией проекта.

Замена модели не должна влиять на архитектуру платформы.

---

## Процесс важнее отдельных запросов

Любая задача проходит полный жизненный цикл.

Создание задачи

↓

Анализ

↓

Планирование

↓

Реализация

↓

Тестирование

↓

Ревью

↓

Документирование

↓

Pull Request

↓

Завершение

Управление этим процессом является основной функцией AIDA.

# 3. Архитектурные принципы

## 1. Orchestration over Integration

AIDA управляет инженерными процессами, а не отдельными интеграциями.

---

## 2. Project Intelligence First

Любое инженерное решение должно приниматься на основе Project Intelligence.

Модель никогда не должна полагаться исключительно на собственные знания.

---

## 3. Context is Everything

Каждая роль получает только релевантный контекст.

Передача полного проекта считается архитектурной ошибкой.

---

## 4. Roles over Models

Все процессы работают с ролями.

Модель является лишь реализацией роли.

---

## 5. Explainability by Default

Каждое значимое действие сопровождается объяснением.

Пользователь должен понимать:

- что произошло;
- почему это произошло;
- какие данные использовались.

---

## 6. Human Authority

Последнее инженерное решение всегда остается за человеком.

AIDA не выполняет необратимые действия без подтверждения пользователя.

---

## 7. Configuration over Code

Поведение платформы определяется конфигурацией.

Добавление новой роли, модели, рабочего процесса или провайдера не должно требовать изменения ядра.

---

## 8. Everything is an Artifact

Любой значимый результат работы становится артефактом проекта.

Артефакты автоматически пополняют Project Intelligence.

---

## 9. Continuous Intelligence Growth

После завершения каждой задачи Project Intelligence становится богаче.

Новые знания не должны теряться.

Они становятся частью интеллектуальной модели проекта.

---

## 10. AI-Agnostic Core

Ядро AIDA полностью независимо от конкретных AI-провайдеров и моделей.

Взаимодействие осуществляется исключительно через единые интерфейсы платформы.
